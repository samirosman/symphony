# Clean-room rules

These keep Symphony legally safe. Not legal advice; get a real review before
any release.

**Allowed inputs**
- Toon Boom's public documentation, public tutorials, talks and videos, used
  to learn *what features do and how they behave*.
- Our own observation of how the app behaves, by people with a legitimate
  licence, written down as behaviour notes in our own words.
- Files that users created themselves, for import/interop work.

**Never**
- Decompile, disassemble or debug Harmony binaries or libraries.
- Copy Toon Boom code, scripts, icons, splash art, sample scenes, brushes,
  palettes or UI images.
- Copy documentation text into this repo. Paraphrase it, and link to it.
- Use "Toon Boom" or "Harmony" in the product name, logo or marketing as
  if affiliated. "Familiar to Harmony users" is fine. "Harmony clone" isn't.
- Ship Toon Boom utilities (such as `tvg2xml`), or anything produced by
  running them on Toon Boom-owned files.

**Generic terms are fine**: xsheet, exposure, peg, composite, onion skin, line
art, colour art, cut-out, bone, envelope. These are industry vocabulary.

**Keymaps and layouts**: we rebuild the behaviour from the published shortcut
list and our own layout. We never import a Toon Boom preference file.
